# Архитектура Legamind

Legamind — настольное приложение для работы с локальными (OpenVINO) и облачными
ИИ-моделями. Ниже — фактическая архитектура проекта, без внешних заимствований.

## Компоненты

```
┌──────────────────────────────────────────────┐
│  UI: SolidJS + Vite (WebView2)               │
│  чат · сессии · модели · RAG · настройки     │
└───────────────┬──────────────────────────────┘
                │ Tauri IPC (invoke/events)
┌───────────────▼──────────────────────────────┐
│  Ядро: Rust (Tauri v2)                       │
│  сессии · провайдеры · инструменты · RAG     │
│  SQLite · бэкапы · секреты · watcher         │
└───────┬───────────────────────┬──────────────┘
        │ HTTP/SSE              │ HTTPS
┌───────▼──────────────┐  ┌─────▼─────────────┐
│ Python sidecar       │  │ Облачные          │
│ OpenVINO GenAI       │  │ провайдеры        │
│ (локальные модели)   │  │ (OpenAI-совм.)    │
└──────────────────────┘  └───────────────────┘
```

- **UI** — SolidJS, собирается Vite в `dist`, работает внутри Tauri/WebView2.
- **Ядро** — Rust-команды Tauri, доступ к SQLite, файловым инструментам, RAG,
  провайдерам, ключам и резервным копиям.
- **Сайдкар** — Python + OpenVINO GenAI, запускается локально на `127.0.0.1`
  со случайным портом. Для пользователя упакован в `legamind-engine.exe`.
- **Облако** — OpenAI-совместимые API и Anthropic; ключи в Windows Credential Manager.

## Данные

`%APPDATA%\com.legamind.app\`

| Путь | Назначение |
|---|---|
| `legamind.db` | сессии, сообщения, память, навыки, настройки, RAG |
| `logs/` | `app.log`, `audit.log`, `prompts.log`, логи движка |
| `backups/` | автокопии базы (DPAPI) |
| `models/` | локальные модели, скачанные мастером |
| `models-cache/` | кэш компиляции OpenVINO |
| `exports/` | экспорт чатов |

Рабочая папка проекта содержит `.legamind/` (бэкапы, `session.json`), `exports/`,
`datasets/`, `notes.md`.

## Поток чата

1. UI вызывает `chat_send`.
2. Rust собирает контекст: система, память, навыки, RAG-фрагменты, вложения.
3. Запрос уходит локальному сайдкару или облачному провайдеру.
4. Ответ стримится событиями `chat:delta`, завершается `chat:done`.
5. Инструменты (`read_file`, `write_file`, `run_command` и др.) выполняются с
   подтверждением, diff, аудитом и бэкапом; результат возвращается в модель.

## RAG

- Индекс — SQLite FTS5 по текстовым файлам рабочей папки.
- Учитывается `.gitignore`; служебные каталоги исключены.
- Чанки с номерами строк; в промпт попадают топ-фрагменты с подписью `путь:строка`.
- Watcher обновляет только изменённые файлы.

## Инструменты и безопасность

- Режимы доверия: только чтение / рабочая папка / полный доступ.
- Запись и команды требуют подтверждения (можно разрешить на сессию).
- Опасные команды блокируются; перед изменением файла создаётся копия.
- Все действия пишутся в `audit.log`.

## Локальные модели

- Пользователь добавляет OpenVINO IR-папку или скачивает готовую модель с
  Hugging Face через мастер.
- Конфиг движка формируется ядром: только пользовательские модели, без встроенных путей.
- Устройства: CPU / GPU / NPU.

## Сборка

- `build-sidecar.ps1` — PyInstaller-сборка автономного движка в `sidecar-dist/`.
- `npx tauri build` — MSI с UI, Rust-ядром и `engine-bin`.
- `e2e/run.ps1` — сквозной UI-прогон установленного приложения.

## Осознанные ограничения

- Windows x64.
- RAG на FTS5, без векторных эмбеддингов.
- Vision — только облачные модели с поддержкой изображений.
- Нет код-сигнинга и автообновления в текущей версии.
