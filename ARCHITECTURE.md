# Legamind — локальная платформа агентов

Вдохновлено архитектурой [HiveMind OS](https://github.com/hivemind-os/hivemind) (MIT), но собрано под наши
условия: Windows + Intel NPU/iGPU, Python, минимум зависимостей.

## Чем отличаемся от HiveMind OS

| HiveMind OS | Legamind |
|---|---|
| Rust, 40+ крейтов, Tauri | Python + SQLite, один процесс |
| Модели через Ollama/облако | llama.cpp (Vulkan) + OpenVINO (NPU) |
| Сборка из исходников | запуск из папки, без сборки |
| Плагины на TypeScript | скиллы как markdown + python-функции |
| Полноценный workflow-движок | YAML-воркфлоу с 5 типами шагов |

## Что берём (проверенные идеи)

| Идея | Откуда | Зачем нам |
|---|---|---|
| Демон + тонкий UI через HTTP/SSE | `hive-daemon` + Tauri | UI можно переделать, не трогая ядро |
| Сессия = папка workspace + своя SQLite | `sessions/<id>/workspace` | агент не выходит за пределы проекта |
| Динамический набор инструментов | `build_session_tools()` | персоны и права решают, что доступно |
| Память как SQLite + FTS5 + вектора | `hive-knowledge` (sqlite-vec) | локально, без серверов |
| Context map: сжатое описание workspace в промпт | `hive-context-map` | модель «видит» проект, не читая всё |
| Персоны с `allowed_tools` | `persona.yaml` | разные агенты — разные права |
| Approval gates для опасных инструментов | `hive-loop` interaction | shell/запись только с подтверждением |
| Audit log + скан промпт-инъекций | `hive-core`, `hive-risk` | приватность и предсказуемость |
| YAML-воркфлоу со шагами и состоянием в SQLite | `hive-workflow` | повторяемые сценарии |

## Что не берём (лишнее для нас)

- Rust, крейты, Tauri — тяжело собирать и сопровождать.
- Plugin SDK на TypeScript, песочница Node.
- MCP Apps с iframe, canvas, iWork-парсер.
- Connectors (календари, почта) — пока не нужны.
- Отдельный `hive-cli` — обойдёмся командами демона.

## Архитектура

```
┌──────────────────────────────────────────────┐
│  UI (web, localhost)                         │
│  чат · сессии · память · воркфлоу · настройки │
└───────────────┬──────────────────────────────┘
                │ HTTP + SSE
┌───────────────▼──────────────────────────────┐
│  legamind daemon (Python)                    │
│                                              │
│  chat ── loop ── tools ── approvals          │
│    │       │                                 │
│    │       └── model router                  │
│    │              ├── llama.cpp  :8080       │
│    │              └── OpenVINO   (NPU/GPU)   │
│    │                                         │
│    ├── memory  (SQLite FTS5 + embeddings)    │
│    ├── workspace index + context map         │
│    └── workflows (YAML + SQLite state)       │
└──────────────────────────────────────────────┘
```

## Хранилище

`%LOCALAPPDATA%\legamind\`

| Путь | Назначение |
|---|---|
| `config.yaml` | модели, провайдеры, персоны |
| `memory.db` | память: факты, эпизоды, FTS5, вектора |
| `workflows.db` | определения и состояние воркфлоу |
| `audit.log` | журнал действий инструментов |
| `sessions/<id>/workspace/` | рабочая папка сессии |
| `sessions/<id>/session.json` | сообщения и метаданные |
| `personas/<name>/persona.yaml` | роль, инструменты, промпт |
| `skills/<name>/SKILL.md` | скиллы |

## Модельный слой

Единый интерфейс `chat(messages, tools)` с двумя бэкендами:

1. **llama.cpp server** — OpenAI-совместимый, GGUF-модели, Vulkan на iGPU.
2. **OpenVINO** — наши int4-модели, NPU для лёгких задач, GPU для 14B/30B.

Выбор — по имени модели в конфиге, роутер как `hive-model`.

## Память

| Тип | Что хранит |
|---|---|
| Факты | «в проекте binres используется JFFS2 с таким форматом» |
| Эпизоды | итоги задач: что сделали, чем закончилось |
| Код | пути и краткие описания модулей (индекс workspace) |

Поиск: FTS5 (BM25) + векторное сходство, объединение через RRF.
Вставка в промпт — по бюджету токенов (как «budgeted injection» в MiMo).

## Инструменты (MVP)

| Инструмент | Права |
|---|---|
| `fs.read`, `fs.list`, `fs.grep` | всегда |
| `fs.write`, `fs.patch` | подтверждение |
| `shell.exec` | подтверждение + белый список |
| `memory.save`, `memory.search` | всегда |
| `workflow.run` | подтверждение |

## Воркфлоу

YAML-файл, шаги: `call_tool`, `invoke_agent`, `branch`, `for_each`, `delay`.
Состояние — в `workflows.db`, возобновление после падения.

## Этапы

| Этап | Содержание | Оценка |
|---|---|---|
| **M1** | демон, чат, llama.cpp-бэкенд, сессии | 1 вечер |
| **M2** | память: FTS5 + эмбеддинги, контекст в промпт | 1–2 вечера |
| **M3** | инструменты + approvals + audit | 2 вечера |
| **M4** | web-UI: чат, сессии, память | 2–3 вечера |
| **M5** | персоны, скиллы, воркфлоу | 3–4 вечера |

## Принципы

1. Всё локально: ни одного запроса наружу без явного действия пользователя.
2. Опасное — только через подтверждение.
3. Состояние переживает перезапуск: сессии, память, воркфлоу — в SQLite.
4. Один процесс, без Docker, без сборки.
